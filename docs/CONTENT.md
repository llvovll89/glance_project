# 콘텐츠 구조

- src/content.ts: 공통 타입, 기본 가이드와 학습 데이터 집계
- src/expanded-content.ts: 초기 증상·부품·Windows 기초 확장
- src/library-content.ts: 오류·연결·저장 공간 가이드와 용어
- src/additional-symptoms.ts: 입력·충전·업데이트·앱·프린터 가이드
- src/extended-symptoms.ts: 화면·절전·설치·언어·터치패드 가이드
- src/guide-categories.ts: 증상 분류와 필터
- src/guide-branches.ts: 단계별 결과 질문과 다음 점검 분기
- src/settings-visuals.ts: Windows 11 화면 안내의 경로·번호별 설명·공식 출처와 점검 단계 연결
- src/SettingsVisual.tsx: 설정·작업 관리자 안내 그림과 확대 대화상자
- src/diagnosis-history.ts: 점검 이력 스냅샷·저장 검증·중복 갱신·복사 보고서
- src/DiagnosisHistory.tsx: 이력 목록·메모 수정·복사·개별 삭제·재점검

새 가이드에는 고유 ID, 검색 태그, 점검 단계, 확인 결과와 다음 행동, 관련 용어 ID, 공식 출처를 제공합니다. 새 항목을 분류에 등록하고 npm run verify로 참조와 누락을 검사하세요.

## 점검 이력과 결과 메모

해결 버튼·해결 결과 선택·미해결 기록 버튼으로 현재 점검을 이력에 남깁니다. 점검 ID와 날짜, 당시 증상 제목, 확인 완료한 단계, 선택한 질문과 답변, 상황 선택, 입력한 PC 사양과 메모를 스냅샷으로 보관하므로 이후 가이드나 사양을 수정해도 이전 내용은 유지됩니다. 미해결로 기록할 때 현재 단계가 자동으로 확인 완료 처리되지는 않습니다.

메모는 선택 입력이며 최대 1,000자입니다. 작성 중인 메모와 점검 ID는 기존 진행 저장소의 선택 필드로 저장해 새로고침 후 이어 쓸 수 있습니다. 기존 저장 기록도 읽을 수 있습니다. 같은 점검 ID로 다시 기록하면 이력을 중복 추가하지 않고 내용을 갱신합니다. 이력의 ‘다시 점검’은 새로운 ID로 첫 단계부터 시작하며 이전 이력을 보존합니다.

이력 저장소는 `hanno-diagnosis-history-v1`이며 진행 상태 저장소와 별도입니다. 최대 50개를 보관하고 새 기록 추가로 한도를 넘으면 기존 기록을 자동 삭제하지 않습니다. 저장 실패 시 완료 화면에 오류·재시도 버튼을 표시하고 진행 상태를 지우지 않습니다. 이력 목록은 5개씩 표시하고 개별 삭제·메모 수정·저장된 기록 복사를 지원합니다. 복사에는 작성 중인 수정본이 아닌 마지막으로 저장한 메모가 포함됩니다. 클라우드 동기화는 제공하지 않으며 사이트 데이터 삭제 시 이력도 사라집니다.

`npm run verify`의 `verify-history.mjs`에서 스냅샷·진행 기록 호환·메모 직렬화·보고서·중복 갱신·보관 한도·손상된 저장 데이터·저장소 차단을 검사합니다. 브라우저 테스트는 저장·새로고침·메모 수정·복사·개별 삭제·재점검·저장 실패와 재시도를 검증합니다.

## 설정 화면 그림 안내

네트워크 연결 상태, 소리 출력 장치, 앱별 볼륨, 작업 관리자 프로세스의 안내 그림 4종을 제공합니다. 인터넷·Wi-Fi 목록·이더넷·소리·느려짐 가이드의 관련 점검 6곳에 연결했습니다.

`settings-visuals.ts`의 `screenGuides`에 화면 경로, 여는 방법, 번호별 설명, 유의 사항, 공식 출처와 검토일을 작성합니다. `screenGuideTargets`에서 가이드 ID와 단계 인덱스를 연결합니다. `npm run verify`는 연결한 단계의 존재 여부, 연결의 중복, 안내 내용과 공식 출처, 화면 렌더링을 검사합니다.

그림은 Windows 11 메뉴 구성을 참고한 자체 HTML/CSS 안내도이며 실제 캡처가 아닙니다. 장치 이름·상태·수치는 예시라고 표시합니다. 번호는 그림의 확인 위치와 설명을 연결하며, 그림의 스위치나 볼륨 표현은 PC 설정을 바꾸지 않습니다. 관련 단계에서만 표시하고 확대 대화상자의 닫기·Escape·초점 복귀와 모바일 레이아웃을 브라우저 테스트로 확인합니다.

## 확인 결과에 따른 점검 분기

인터넷·소리·Wi-Fi 목록·유선 연결·느려짐 가이드의 9개 단계에 결과 질문을 제공합니다. `guide-branches.ts`에 가이드 ID, 단계 인덱스, 질문과 선택지를 등록합니다. 선택지의 `target`은 현재보다 뒤의 단계 인덱스 또는 사용자가 해결을 확인하는 `resolved`입니다. 기존 가이드의 공식 출처와 안내 범위 안에서 분기하며, `npm run verify`가 질문·선택지 ID·목적지의 유효성을 검사합니다.

선택한 결과는 진행 상태와 함께 저장하고 복사 기록에 포함합니다. 과거 단계의 결과를 다시 선택하거나 ‘다음 확인’으로 진행하면 그 단계 이후의 답변과 완료 표시를 지웁니다. ‘다음 확인’은 답변 없이 기존 순서대로 진행하는 경로입니다. 답변 필드가 없는 기존 저장 기록도 이어갈 수 있습니다. 해결을 표시하면 이력을 보관한 뒤 저장된 진행 기록을 지우며, 이력 저장 실패 시 진행 기록을 유지합니다.
