# 초보자 사용 테스트 진행표

상태: 참여자 테스트 미실시. 아래는 진행 절차이며 사용자 관찰 결과가 아닙니다.

## 준비

- 컴퓨터 문제 해결에 익숙하지 않은 참여자 5명을 목표로, 1명당 약 15~20분 진행합니다. 소수의 관찰로 통계적 성능을 주장하지 않습니다.
- 평소 사용하는 기기·브라우저로 접속합니다. 모바일 참여자를 2명 이상 포함하고 화면 크기와 브라우저 버전을 기록합니다.
- 테스트용 새 브라우저 프로필을 사용합니다. 실제 PC 사양·개인 메모 대신 아래의 예시 정보만 입력합니다.
- 진행자는 “사람을 평가하는 것이 아니라 사이트에서 막히는 곳을 찾는 테스트”라고 설명합니다. 화면·음성 기록은 참여자가 동의한 경우에만 합니다.
- 사이트의 기능 위치나 정답은 먼저 알려주지 않습니다. 막히면 30초 정도 관찰한 뒤 필요한 도움을 기록하고 안내합니다. 실제 고장이나 네트워크 차단을 유발하지 않습니다.

## 과제

| 과제 | 참여자에게 읽어 줄 상황 | 성공을 확인할 기준 | 관찰 시간 목표 |
|---|---|---|---|
| 증상 점검 | 휴대폰에서는 인터넷이 되는데 PC에서는 여러 사이트가 안 열립니다. 어디부터 확인하면 좋을까요? 연결을 확인한 뒤 정상 작동했다고 가정하고 결과를 남겨 주세요. | 인터넷 가이드, PC만 안 되는 결과, 연결 점검, 해결 결과, 점검 이력을 도움 없이 찾음 | 3분 |
| 이어하기 | 새로운 점검에서 한 단계를 진행한 뒤 화면을 새로고침해 주세요. 아까 확인하던 곳으로 돌아갈 수 있나요? | 진행 중인 점검과 이어하기를 찾고 이전 단계가 유지됨을 알아봄 | 2분 |
| 개념 학습 | RAM과 저장장치가 어떻게 다른지 이 사이트에서 알아보고 본인의 말로 설명해 주세요. | 관련 설명을 찾고 전원을 끈 뒤에도 파일을 보관하는 장치를 구분함 | 2분 |
| PC 기록 | 실제 사양 대신 이름 ‘테스트 PC’, RAM ‘16 GB’를 기록하고 새로고침해 주세요. 다른 기기에서도 자동으로 보일까요? | 필요한 두 항목만 저장하고 복원 확인, 이 브라우저에만 저장됨을 이해함 | 3분 |
| 명령어 연습 | 실제 파일을 건드리지 않고 현재 위치를 확인하는 명령을 연습해 주세요. 잘못 입력하면 어떻게 되나요? | 예제 넣기·실행·출력을 찾고 가상 연습임을 이해함 | 3분 |

관찰 시간 목표는 테스트 판단을 돕는 기준입니다. 이를 넘겨도 즉시 실패로 단정하지 말고 원인을 기록합니다.

## 진행자가 기록할 내용

- 참여자 코드는 P01~P05로 적고 이름·연락처·실제 PC 사양을 저장소에 남기지 않습니다.
- 각 과제의 시작·끝 시각, 도움 없는 성공/도움 후 성공/미완료, 도움을 준 횟수와 시점, 첫 선택, 되돌아간 지점을 기록합니다.
- 종료 후 쉬웠던 정도를 1~5점으로 묻고 “가장 헷갈린 표현이나 버튼은 무엇이었나요?”, “예상과 다르게 동작한 곳은 있었나요?”를 묻습니다.
- 발언은 실제로 들은 내용만 인용합니다. 진행자의 해석과 참여자의 표현을 구분합니다.

|---|---|---|---|---|---|---|---|

## 결과에 따른 다음 작업

- 같은 핵심 과제에서 2명 이상 막히거나 기록 손실·잘못된 안내가 관찰되면 우선 수정합니다.
- 5명 중 4명 이상이 핵심 점검·이어하기 과제를 도움 없이 마치는지 살펴봅니다. 미달하면 진입 경로와 문구를 수정하고 새 참여자에게 재확인합니다.
- 실제 참여자 수, 기기, 수행 결과가 채워진 뒤에만 사용자 테스트를 완료로 표시합니다. 자동 E2E와 에이전트 점검을 참여자 결과에 합산하지 않습니다.
