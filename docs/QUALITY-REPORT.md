# 품질 개선 검증 기록

기준일: 2026-10-30. 자동화·에이전트 점검과 실제 사용자·기기 검증을 구분합니다.

## 모바일·키보드

- Chromium 데스크톱·모바일 에뮬레이션에서 320·390·768·1024 CSS px, 밝은·어두운 테마를 확인했습니다. 데스크톱은 320·768·1024, 모바일은 320·390을 담당합니다.
- 문제 해결, 부품 학습, 용어 사전, 퀴즈, PC 사양 가져오기와 펼친 명령, 명령어 연습, CPU 설명 창을 확인했습니다. 페이지와 조작 요소의 가로 넘침, 설명 창 내부 넘침 검사가 통과했습니다.
- 본문 바로가기, 설명 창의 첫 초점·초점 유지·Escape 닫기·열었던 버튼으로 복귀, 설정 그림 닫기 후 복귀를 확인했습니다.
- 1280px 화면을 200% 확대했을 때와 같은 640×450 CSS px 뷰포트에서 점검과 설정 그림을 확인했습니다. 이는 재배치 검사이며 브라우저의 실제 확대 조작이나 스크린리더·실물 모바일 검증을 대신하지 않습니다.
- 분야 버튼 묶음을 이름 있는 `group`으로 지정하고, 퀴즈의 다음 문제·다시 시작 시 질문 제목으로 초점을 이동하도록 수정했습니다.
- 관련 E2E 10개 통과. 기존 56개와 별도로 추가한 검사입니다.

## 초기 로딩

- PC 사양, 명령어 연습, 용어 사전·퀴즈를 동적으로 불러옵니다. 첫 화면에서 세 모듈을 요청하지 않고 해당 메뉴를 열 때 가져오는 브라우저 검사가 통과했습니다.
- 모바일·키보드 수정 직후의 단일 초기 JS 583.99KB에서, 분리 후 초기 JS와 정적 공통 의존성을 합한 537.91KB로 약 7.9% 줄었습니다. 첫 파일만 비교하지 않았습니다. 초기 gzip 합계는 Node `gzipSync` 기준 160.34KB입니다.
- `npm run verify:performance`는 빌드 manifest를 따라 초기 정적 의존성을 모두 합산합니다. 초기 JS 550,000바이트·gzip 165,000바이트 예산과 세 메뉴의 초기 의존성 제외를 CI에서 검사합니다.
- 메뉴 로딩 실패 시 안내와 같은 URL에서 다시 불러오기를 제공하며, 실패 후 재시도 E2E가 통과했습니다. 네트워크 환경별 실제 시간 개선이나 사용자 Core Web Vitals를 측정한 결과는 아닙니다.
